flaky (2014)universal cell

Luo et al. (2014, FSE) flaky-test empirical analysis.

What this model says

Test flakiness compounds. A flaky test slows CI feedback, which delays bug discovery, which lets defects accumulate. The accumulated defects in turn surface as more flaky tests (real-bug-masquerading-as-flake), and the cycle deepens.

The model treats Flaky as a stock that grows when CI-Discipline weakens; CI-Discipline weakens when there are too many flakes to triage. The thesis is one of negative feedback loop dominance.

Intuition: A team that tolerates flaky tests gets more flaky tests. The flake-mask probability is the runaway parameter.

Success measure (model.y)

Done − 3·Esc — flakes that mask real bugs cost 3×.

Lower penalty than brooksq because not every flake masks a bug; but real bugs masked by flakes are 3× worse than open work.

Conjecture (model.rq)

Flake-mask probability 0.01 → 0.4 dominates output.

A 40× shift in mask probability collapses the feedback loop into runaway mode. CONFIRM at default.

def flaky():
  """Luo et al. [11]: flaky tests erode trust -> erode coverage.
  RQ: high flake_rate erodes useful coverage."""
  init = {'Tests':[100,0,500,'tests'], 'Flakes':[5,0,500,'tests'], 'Bugs':[0,0,500,'bugs'],
          'flake_rate':[0.02,0,0.2,'frac/tick'], 'invest_base':[5,0,20,'frac/tick'],
          'fix_coef':[0.15,0,1,'frac/flake'], 'leak_coef':[3,0,10,'frac/flake']}

  def step(dt, t, u, v):
    cover = u.Tests / max(1, u.Tests + u.Flakes)
    add   = u.invest_base * cover
    flake = u.Tests * u.flake_rate
    fix   = u.Flakes * u.fix_coef * cover
    leak  = u.Flakes / max(1, u.Tests + u.Flakes) * u.leak_coef
    v.Tests = u.Tests + dt * (add - flake)
    v.Flakes = u.Flakes + dt * (flake - fix)
    v.Bugs = u.Bugs + dt * leak
    for p in ('flake_rate','invest_base','fix_coef','leak_coef'):
      setattr(v, p, getattr(u, p))

  def y(out):
    end = out[-1][1]
    return end.Tests - end.Bugs

  def rq(bg=None):
    bi = init if bg is None else bg
    return verdict("high flake_rate erodes useful coverage",
                   y(run({**bi, 'flake_rate':[0.02,0,0.2,'frac/tick']}, step)),
                   y(run({**bi, 'flake_rate':[0.10,0,0.2,'frac/tick']}, step)), 'down')

  return Model(init, step, y, rq, 'flake_rate')

What we learned

No empirical results. flaky is dark for a tractable reason — the data exists, no parser yet.

A future session could build a GH Actions retry-detector + lift flaky empirically.

Implications

  • Buildable in 1–2 sessions: unlike aiwork or teamtopo, flaky's data exists. The parser is the only missing piece.
  • Cross-project ground truth available: iDFlakies (Lam et al. 2019) provides a labelled flaky-test corpus that could validate any detector built here.
