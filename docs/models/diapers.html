What this model says

Smallest non-trivial SD model. Two stocks, three flows, one weekly event, one fault. Models a household's diaper logistics: clean diapers arrive in batches, get consumed daily, dirty ones pile up until laundry day clears them — unless laundry day is forgotten.

Diapers is the canary. If the framework cannot integrate two coupled stocks under an event-driven flow schedule, no richer model will run either. The V&V suite hits diapers first; green here means the harness is healthy.

Intuition: clean stock C drains at constant rate r=8 per day (one per child-event), is refilled by q=70 every Saturday (big-box restock), and dirty stock D accumulates from the same r outflow, draining via s (washing) only on Saturdays — except on day 27, when laundry was forgotten and s=0 regardless.

Success measure (model.y)

Final dirty-stock level D(tmax).

A healthy schedule lands D near zero each week. A missed laundry day spikes D by a full week's accumulation. The success measure is therefore both a level and an alarm.

Conjecture (model.rq)

Skipping one laundry day leaves persistent residue.

Verdict mechanics: compare D(tmax) with and without the day-27 forget. The model produces a CONFIRM verdict because the missed clear is never recovered — subsequent Saturdays only drain that Saturday's accumulation. A forgotten event causes durable system drift.

Stress-matrix cell

Diapers sits in process-conditional: robust to input perturbation (initial C/D levels wash out within one week), fragile to parameter perturbation (changing q or the saturday cadence breaks the residue verdict).

The SD model

From models/sd.py. S(x) builds a Stock at level x; F(x) builds a Flow at rate x; o(...) packs a namedtuple-like state.

class Diapers(Model):

  def have(i):
    # Two stocks: C (clean), D (dirty). Three flows: q (in), r (C->D), s (out).
    return o(C = S(100), D = S(0),
             q = F(0),   r = F(8), s = F(0))

  def step(i, dt, t, u, v):
    # Saturday = day index 6 mod 7. Laundry day.
    def saturday(x): return int(x) % 7 == 6

    # Stock updates from current flows (Euler integration).
    v.C +=  dt * (u.q - u.r)        # clean fills on q, drains on r
    v.D +=  dt * (u.r - u.s)        # dirty fills on r, drains on s

    # Flow updates: weekly refresh and weekly clear.
    v.q  =  70  if saturday(t) else 0     # restock every Sat
    v.s  =  u.D if saturday(t) else 0     # full drain every Sat

    # The fault: we forgot laundry on day 27. s stays 0.
    if t == 27:
      v.s = 0

The day-27 condition is what makes this model interesting: it injects a single missed event into an otherwise periodic system. The rq conjecture asks whether one forgotten Saturday produces a measurable, persistent change in D(tmax) versus the no-fault counterfactual.

What we learned

If diapers fails the 9-test bank, debugging starts with the engine (run, verdict, opt, stress) rather than with any specific model.

Implications

  • diapers is a contract test — its continued PASS-PASS-...-PASS pattern means the framework still works.
