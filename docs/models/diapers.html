What this model says

The simplest possible model the framework can run: one input variable, one output, no dynamics. It exists not to claim anything about software engineering but to demonstrate the engine end-to-end — that the harness can read a Model namedtuple, run it, and produce a verdict.

If diapers ever fails to execute, the bug is in the framework, not in any model. It is the canary in the coal mine: the V&V suite runs against diapers first, and a green light there means the harness is healthy.

Intuition: No intuition needed — the model has no physical referent. Think of it as a hello-world for compartmental SD.

Success measure (model.y)

The output flow at the final step.

Trivially defined and trivially measured. The model has one flow; its value at tmax is the success measure.

Conjecture (model.rq)

A baseline shift hurts net output.

By construction the model produces a CONFIRM verdict because the shift acts directly on the only flow. The rq exists only to exercise the verdict pipeline.

Stress-matrix cell

diapers lands in process-conditional because its sole parameter dominates the dynamics — perturbing it neutralises the verdict, while perturbing the (trivial) input does not.

The SD model

def diapers():
  """Toy: weekly diaper supply.  Sat = bulk buy + wash all dirty.
  RQ: skip wash on Sat t=13 -> dirty pileup."""
  init = {'Clean':[100,0,200], 'Dirty':[0,0,200], 'Buy':[0,0,100],
          'Use':[8,0,20], 'wash_amt':[0,0,200], 'skip':[0,0,1]}

  def step(dt, t, u, v):
    sat = int(t) % 7 == 6
    v.Clean = u.Clean + dt * (u.Buy - u.Use)
    v.Dirty = v.Dirty + dt * (u.Use - u.wash_amt)
    v.Buy   = 70 if sat else 0
    v.wash_amt = u.Dirty if sat else 0
    if t == 13 and u.skip > 0.5: v.wash_amt = 0
    v.skip = u.skip

  def y(out):
    return min(r.Clean for _, r in out) - 0.5 * max(r.Dirty for _, r in out)

  def rq(bg=None):
    bi = init if bg is None else bg
    return verdict("skip wash@t=13 -> Dirty pileup",
                   y(run({**bi, 'skip':[0,0,1]}, step)),
                   y(run({**bi, 'skip':[1,0,1]}, step)), 'down')

  return Model(init, step, y, rq, 'skip')

What we learned

diapers does not produce empirical findings. Its role is purely to confirm that the framework's V&V machinery executes correctly.

If diapers fails the 9-test bank, debugging starts with the engine (run, verdict, opt, stress) rather than with any specific model.

Implications

  • diapers is a contract test — its continued PASS-PASS-...-PASS pattern means the framework still works.
  • Two known FAIL cells (mr_scale, mr_dt_halving) are diagnostic, not problematic — they document where the toy fails to mirror physical SD behaviour.
