congruence_motif (2022)universal cell

Mauerer et al. (2022, IEEE TSE) — motif-based socio-technical congruence; companion to congruence (smells-based).

What this model says

Dev-pairs who CO-TOUCH the same source file (or two dep-linked source files) SHOULD COMMUNICATE about it. When they don't, anti-motif counts accumulate as realized coordination gaps. Mauerer et al. (2022 IEEE TSE) operationalize this via four motif templates over a merged dev–file–dep graph and count subgraph isomorphisms (VF2 algorithm).

The model tracks Devs, Files, and Bugs. Each tick, the active dev-pair population co-touches files at pair_touch_rate; the fraction (1 − comm_rate) become anti-triangles (file-level) or anti-squares (dep-level). Each anti-motif event accrues bugs at bug_per_antimotif; bug_pay_rate drains them. Higher communication closes more coordination gaps → fewer Bugs accumulate. This is the motif-based variant of the same SE thesis the congruence model encodes via the smells/Louvain path.

Intuition: When two devs touch the same file but never email or comment, every such co-touch is a future bug waiting to happen.

Success measure (model.y)

Bugs at end of run (lower = better).

Total bugs accumulated from anti-motif events minus paydown. Success = LOW Bugs. rq() uses expect='down': high comm should produce lower Bugs.

Conjecture (model.rq)

Raising comm_rate from 0.2 (fragmented) to 0.8 (well-coordinated) lowers final Bugs.

CONFIRM with gap ≈ −69 at default. The two-arm comparison is Mauerer's central STC claim distilled to a controlled experiment.

def congruence_motif():
  """**Motif-based variant** of socio-technical congruence (STC).
  Companion to the smells-based `congruence` model above.

  Source: Mauerer, Joblin, Tamburri, Paradis, Kazman, Apel (2022).
  "In Search of Socio-Technical Congruence: A Large-Scale
  Longitudinal Study." IEEE TSE 48(8):3159-3184.
  doi:10.1109/TSE.2021.3082074. Operationalized in kaiaulu
  R/motif.R via igraph::count_subgraph_isomorphisms over four
  motif templates.

  Thesis (Cataldo/Mauerer): dev-pairs who CO-TOUCH source files
  (or dep-linked files) SHOULD COMMUNICATE about it. When they
  don't, anti-motif counts (anti-triangle, anti-square) accumulate.
  Anti-motifs realize the coordination gap as defects.

  Motif accounting per tick:
    Triangle      = pair comm + co-touch file        (positive)
    Anti-Triangle = pair NO-comm + co-touch file     (negative)
    Square        = pair comm + co-touch dep-linked  (positive)
    Anti-Square   = pair NO-comm + co-touch dep-linked (negative)

  Stocks: Devs, Files, Bugs (success = LOW final Bugs).
  Ctrl: comm_rate. RQ: high comm (0.8) reduces Bugs vs low comm (0.2).

  Lift (per project, per snapshot, via kaiaulu motif_factory +
  igraph::count_subgraph_isomorphisms over the merged
  git-reply-dependency network): produces Tri/AntiTri/Sq/AntiSq
  integer counts plus n_devs, n_files, n_deps. Calibrate `comm_rate`
  from the empirical ratio (Tri+Sq)/(all four)."""
  init = {'Devs':[30,2,200,'devs'], 'Files':[100,10,5000,'files'],
          'Bugs':[0,0,500,'bugs'],
          # ctrl: probability a co-touching dev-pair communicates
          'comm_rate':[0.5,0,1,'frac'],
          # Network params (literature priors):
          'dep_density':[0.2,0,1,'frac/pair'],         # cross-file dep frequency
          'pair_touch_rate':[0.05,0,1,'frac/pair/tick'],  # avg co-touch frequency
          # Bug accounting:
          'bug_per_antimotif':[0.5,0,5,'bugs/event'],
          'bug_pay_rate':[0.1,0,1,'frac/tick']}

  def step(dt, t, u, v):
    # Mauerer 2022 motif accounting at flow level:
    # enumerate dev-pairs that could co-touch this tick.
    active_pairs = u.Devs * (u.Devs - 1) / 2 * u.pair_touch_rate
    # Of those, the fraction that DON'T communicate become anti-triangles.
    antitri_flow = active_pairs * (1 - u.comm_rate)
    # Subset of pairs that touch DEP-LINKED file pairs (square family).
    cross_pairs  = active_pairs * u.dep_density
    antisq_flow  = cross_pairs * (1 - u.comm_rate)
    # Each anti-motif event accrues some Bugs; refactor pays them down.
    bugs_born = (antitri_flow + antisq_flow) * u.bug_per_antimotif
    bugs_paid = u.Bugs * u.bug_pay_rate
    v.Devs  = u.Devs
    v.Files = u.Files
    v.Bugs  = max(0, u.Bugs + dt * (bugs_born - bugs_paid))
    for p in ('comm_rate','dep_density','pair_touch_rate',
              'bug_per_antimotif','bug_pay_rate'):
      setattr(v, p, getattr(u, p))

  def y(out):
    # Final Bugs is the success measure. Lower = better.
    # rq() uses expect='down' so CONFIRM means y1 < y0 (more comm → fewer Bugs).
    return out[-1][1].Bugs

  def rq(bg=None):
    # Two-arm comparison: low comm (0.2, communication-fragmented)
    # vs high comm (0.8, well-coordinated). Mauerer's thesis says
    # the high-comm arm produces fewer defects via fewer anti-motifs.
    bi = init if bg is None else bg
    return verdict("comm_rate 0.8 reduces Bugs vs 0.2 (Mauerer 2022 STC)",
                   y(run({**bi, 'comm_rate':[0.2,0,1,'frac']}, step)),
                   y(run({**bi, 'comm_rate':[0.8,0,1,'frac']}, step)), 'down')

  return Model(init, step, y, rq, 'comm_rate')

Data lift

Lifted via the kaiaulu motif pipeline (R/motif.R + R/network.R), confirmed against the kaiaulu vignette vignettes/motif_analysis.Rmd:

gitlog ──> bipartite (author-file)         ─┐
replies ─> bipartite (dev-thread) ──proj──> ─┼─> merged graph
deps ────> file-file network                ─┘            │
                                                          ▼
                                       igraph::count_subgraph_isomorphisms
                                       over { triangle, anti_triangle,
                                              square, anti_square }
                                                          │
                                                          ▼
                              congruence_motif = (Tri + Sq) / sum(all 4)

Six-step method (parallels the smells-based congruence path; uses the same identity-match prerequisite):

  1. Parse gitlog → transform_gitlog_to_bipartite_network(mode="author-file").
  2. Parse replies (mbox / GitHub) → transform_reply_to_bipartite_network() → bipartite_graph_projection() for dev-dev edges.
  3. Parse dependencies → transform_dependencies_to_network(dependency_type="file") (or transform_r_dependencies_to_network() for R).
  4. identity_match(name_column=c("author_name_email","reply_from")) — required cross-source bridge.
  5. Merge all three networks into a single combined graph; cast node colours to numeric for VF2.
  6. For each motif in {triangle, anti_triangle, square, anti_square}: motif_factory(name) → igraph::count_subgraph_isomorphisms(motif, network, method="vf2"). Emit four integer counts + n_devs, n_files, n_deps, plus the derived ratio.

Vignette example on kaiaulu itself: triangle=34, square=32 (anti variants available via motif_factory("anti_triangle") etc.). Calibrate comm_rate from the empirical ratio (Tri+Sq)/(Tri+AntiTri+Sq+AntiSq).

Three operationalizations of the same SE thesis: kaiaulu carries the smells path (R/smells.R, Louvain communities, Catolino 2019) shipped as congruence; the motif path (R/motif.R, VF2 subgraph isomorphism, Mauerer 2022) shipped as this model; and a possible third Cataldo matrix path (CR ∩ CA / |CR|, three sub-variants reviewer-requested in 2022) still queued as congruence_cataldo per TODO UU.

count_motif <- function(motif_name, g) {
  m <- motif_factory(motif_name)
  img <- igraph::graph_from_data_frame(
    d = m$edgelist, directed = FALSE, vertices = m$nodes)
  V(img)$color <- ifelse(V(img)$color == "black", 1, 2)
  igraph::count_subgraph_isomorphisms(
    img, g, method = "vf2",
    edge.color1 = NULL, edge.color2 = NULL)
}

counts <- list(
  Triangle    = count_motif("triangle",      g),
  AntiTri     = count_motif("anti_triangle", g),
  Square      = count_motif("square",        g),
  AntiSquare  = count_motif("anti_square",   g)
)
print(unlist(counts))

ratio <- (counts$Triangle + counts$Square) /

The vignette example on kaiaulu itself reports triangle=34, square=32 (positive motifs); anti variants are available via motif_factory("anti_triangle") etc. but were not enumerated in the vignette demo. A complete lift run across the 8-project family (Helix, junit5, Ambari, kaiaulu, airflow, openssl, tomcat, camel) would yield the cross-project ratio variance — that variance is what calibrates the comm_rate default and provides the family-member coherence test. Helix is the natural first target since identity_match is already wired in lift_congruence.Rmd (the smells-variant lift) and the merged dev-file-dep graph carries over directly.

Implications

  • Two model pages for one SE thesis: same coordination-gap claim, two different mathematical surfaces (Louvain community detection vs VF2 subgraph isomorphism). The framework's job is to triage which surface gives the more falsifiable measurement.
  • Anti-motif counts are the leverage measurement: not the triangle/square counts themselves (which scale with project size) but the RATIO (Tri+Sq)/(all four). This ratio normalises across project sizes and is the headline calibration target.
  • Cross-validation with smells variant: on the same project, the smells path's Brokers count and the motif path's anti-triangle count should correlate (both measure coordination gaps). High correlation → either method is fine. Low correlation → the methods disagree on what 'coordination gap' means and the SE community needs to pick one.
  • Cataldo's matrix-form variants (TODO UU) constitute a third operationalization (CR ∩ CA / |CR|). Shipping all three as separate SD models gives reviewers the head-to-head methodological comparison the 2022 reviewers asked for.
