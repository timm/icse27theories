Goel-Okumoto NHPP-style reliability growth.

What this model says

A software system contains an unknown pool a of latent defects. As testing proceeds, defects are discovered at a rate proportional to the remaining latent stock — yielding the canonical exponential N(t) = a·(1 − e−bt). The discovery rate b is per-bug; the asymptote a is the eventual total.

Mathematically the same as radioactive decay. Empirically it captures the often-observed pattern that big systems converge on their full bug count: the discovery rate slows because the un-found pool shrinks, not because testing got worse.

Intuition: Each bug is independently exposed by review, testing, or production use. Marginal discovery slows as you exhaust the easy ones.

Success measure (model.y)

Cumulative Fixed at the final timestep.

Higher is better — more defects resolved. In the SD encoding, Latent is the initial pool, Found drains from it at rate b, and Fixed accumulates from Found at the repair rate.

Conjecture (model.rq)

Doubling initial Latent approximately doubles eventual Fixed.

A linearity claim: the recovery process is proportional to the input. CONFIRM = linearity holds. REFUTE = recovery saturates (sub-linear) or compounds (super-linear). Goel-Okumoto's integral is mathematically linear in a, so the default config CONFIRMs.

Stress-matrix cell

bugs sits in process-conditional because input perturbation (Latent count) cannot break the linearity, but parameter perturbation (find_rate, fix_rate near zero) freezes the system into neutral verdicts.

The SD model

From paper/sd.py:

def bugs():
  """Goel-Okumoto [2]: exponential reliability growth.
  RQ: 2x initial Latent -> ~2x eventual Fixed (linearity of recovery)."""
  init = {'Latent':[100,0,200,'bugs'], 'Found':[0,0,200,'bugs'], 'Fixed':[0,0,200,'bugs'],
          'find_rate':[0.15,0.01,0.5,'frac/tick'], 'fix_rate':[0.5,0.05,1,'frac/tick']}

  def step(dt, t, u, v):
    find = u.Latent * u.find_rate
    fix  = u.Found  * u.fix_rate
    v.Latent = u.Latent - dt * find
    v.Found  = u.Found  + dt * (find - fix)
    v.Fixed  = u.Fixed  + dt * fix
    v.find_rate, v.fix_rate = u.find_rate, u.fix_rate

  def y(out):
    """Mid-curve recovery (t=10 of 20): tests scaling, not asymptote.
    Asymptote is always ~1.0 by construction (exponential decay)."""
    mid_idx = len(out) // 2
    return out[mid_idx][1].Fixed

  def rq(bg=None):
    bi = init if bg is None else bg
    return verdict("2x initial Latent -> ~2x mid-curve Fixed",
                   y(run({**bi, 'Latent':[50,0,200,'bugs']}, step)),
                   y(run({**bi, 'Latent':[100,0,200,'bugs']}, step)), 'up')

  return Model(init, step, y, rq, 'Latent')

Data lift

The lift fits Goel-Okumoto to a project's cumulative bug-close trajectory. Two source variants:

  • GitHub issues — filter on label bug, use closed_at. Works on Helix (170 closed bugs) and kaiaulu (22).
  • JIRA — filter on issuetype = Bug, use resolutiondate. Works on camel (185 resolved).

Full notebook: lifts/lift_bugs.Rmd. R chunks below show the substantive fit logic.

rm(list = ls())
seed <- 1
set.seed(seed)
require(kaiaulu); require(data.table); require(stringi)
require(knitr); require(yaml); require(jsonlite)
source("functions.R")
gh_issue_glob <- "/Users/timm/Downloads/helix/github/apache_helix/issue/*.json"
files <- Sys.glob(gh_issue_glob)
cat("Issue files:", length(files), "\n")

issues <- rbindlist(lapply(files, function(f) {
  d <- fromJSON(f, simplifyVector = FALSE)
  if (is.list(d) && !is.null(d[[1]]$id)) {
    # list of issues
    rbindlist(lapply(d, function(i) {
      labels <- vapply(i$labels %||% list(), `[[`, "", "name")
      data.table(
        id        = as.integer(i$id %||% NA),
        state     = i$state %||% NA_character_,
        labels    = paste(labels, collapse = ";"),
        closed_at = i$closed_at %||% NA_character_
      )
    }), fill = TRUE)
  } else if (is.list(d) && "issues" %in% names(d)) {
    rbindlist(lapply(d$issues, function(i) data.table(
      id = as.integer(i$id %||% NA),
      state = i$state %||% NA_character_,
      labels = "",
      closed_at = i$closed_at %||% NA_character_
    )), fill = TRUE)
  } else NULL
}), fill = TRUE)

cat("Total issues parsed:", nrow(issues), "\n")
cat("States:\n"); print(table(issues$state))
bugs <- issues[grepl("bug", labels, ignore.case = TRUE) &
               !is.na(closed_at) & closed_at != ""]
cat("Bug-labeled + closed:", nrow(bugs), "\n")
bugs[, closed_ts := as.POSIXct(closed_at, format = "%Y-%m-%dT%H:%M:%SZ",
                               tz = "UTC")]
setorder(bugs, closed_ts)
t0       <- min(bugs$closed_ts)
rel_t    <- as.numeric(difftime(bugs$closed_ts, t0, units = "secs"))
cum_N    <- seq_along(rel_t)
mean_N   <- mean(cum_N)
ss_tot   <- sum((cum_N - mean_N)^2)
a_max    <- max(cum_N) * 1.2
best     <- list(a = NA, b = NA, sse = Inf)
for (a in a_max * c(0.8, 1.0, 1.2, 1.5, 2.0, 3.0)) {
  for (b in c(1e-9, 1e-8, 1e-7, 1e-6, 1e-5, 1e-4)) {
    pred <- a * (1 - exp(-b * rel_t))
    sse  <- sum((pred - cum_N)^2)
    if (sse < best$sse) best <- list(a = a, b = b, sse = sse)
  }
}
r2 <- 1 - best$sse / ss_tot
cat(sprintf("Goel-Okumoto: a=%.2f  b=%.3e  R^2=%.4f\n",
            best$a, best$b, r2))
span_days <- as.numeric(difftime(max(bugs$closed_ts), t0, units = "days"))
cat(sprintf("Span: %.1f days\n", span_days))
dir.create("../outputs", showWarnings = FALSE)
out <- data.table(
  project         = "helix",
  n_issues_total  = nrow(issues),
  n_bugs_closed   = nrow(bugs),
  gokumoto_a      = best$a,
  gokumoto_b      = best$b,
  fit_r2          = r2,
  span_days       = span_days,
  seed            = seed
)
fwrite(out, "../../paper/outputs/lift_bugs_helix.csv")
kable(out)

What we learned

Fits across three projects all conform to Goel-Okumoto shape with moderate to high R². None of the three have saturated — they're all in the early-discovery regime where the linearity thesis cannot be directly falsified.

project n_bugs a (asymptote) b (rate) R² span source
Helix 170 244.80 1.0e-08 0.62 800d GH bug-label
kaiaulu 22 26.40 1.0e-08 0.91 1600d GH bug-label
camel 185 177.60 1.0e-07 0.60 652d JIRA Bug-type

The smaller project (kaiaulu) paradoxically gives the tightest fit — fewer outliers, less seasonality. The asymptote a values exceed the observed counts in each case, projecting future discovery beyond the observed window. None saturated: linearity cannot be falsified at these horizons.

Implications

  • Linearity holds but isn't tested: rq() verifies mathematical linearity; the empirical fit verifies the curve shape; neither tests the saturation-regime breakdown.
  • Smaller projects fit better: kaiaulu R²=0.91. Possibly because small projects have fewer regime changes.
  • Source affects answer: GH label bug and JIRA issuetype=Bug are not identical. Future cross-check on Helix using the cleaned JIRA dump.
