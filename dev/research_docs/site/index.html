The project turns each law into a small simulation, checks that the simulation is a sound machine (internal tests), and then asks whether real projects sit in the region where the law holds (external tests). Part A built the catalogue and the data pipeline. Part B pushed Brooks' Law through many scenarios. Part C made that testing generic and evidence-driven, and applied it to two more laws: aiwork (AI-assisted coding) and archpat (architectural patterns as repair).

Headline results

  1. No law is simply true or false. Each holds only when particular support factors are present. The useful output is a map of where it holds, plus a test of whether a given project sits inside it.
  2. All three turn on the price of the lever. That is coordination for Brooks, verification time for aiwork, and migration effort for archpat. The original models fixed that price or left it out.
  3. Real data overturned most defaults. Helix's onboarding drag is about 1/24 of the default. AI-written lines in Aider churn about 1.33× (the model assumes 3×). Patterned Helix files are only 0.68–0.83× as bug-prone (the model assumes 0.25×).
  4. Sample size bought nothing; neighbourhood size did. Run 100k times at ±15%, Brooks holds 100% of the time. Sampled over its declared ranges, the original model holds about 10% of the time; the standard model, with the missing structures added, 44%.
